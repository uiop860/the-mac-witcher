## conductor: Hardened Space-membership semantics after live end-to-end audit
- **What:** Space-less offscreen windows are rejected only when they are neither minimized nor owned by a hidden app. Nonempty Space membership is treated as stronger identity evidence than title de-duplication, and private CGS functions are resolved dynamically so missing symbols fail open.
- **Why:** Live Ghostty data proves Space membership separates the two logical windows from tab surfaces, but an empty Space list is a broader invisible-window bucket that can include minimized and hidden windows. Same-title windows on other Spaces are also legitimate and must not be collapsed.

## worker: Diagnosed why mwitch stopped switching windows on this machine
- **Did:** Diagnosed why mwitch stopped switching windows on this machine and shipped a fix into the installed app. Not a permissions problem (unlike the 2026-08-21 incident): the process was alive, Accessibility + Screen Recording were granted, the event tap was live and Cmd+Tab was reaching it. The failure was downstream. mwitch preselects list index 1 on the assumption that index 0 is the window you are currently in, and that invariant was broken two ways. (1) WindowRecencyTracker seeds the MRU head from kAXFocusedWindowAttribute, but for natively tabbed apps that returns the focused TAB surface, not the on-screen window: Ghostty reported wid=132 and Arc wid=15274, neither of which WindowEnumerator will ever list (off-screen, no Space membership, AX-unresolvable). Seating an unlistable id at the MRU head makes Cmd+Tab land on an arbitrary row. (2) The process had been running 3.5 days accumulating dead Ghostty window ids, and one phantom surface (wid=10742) still reported Space membership so it was listed but could not be activated. Fix: WindowEnumerator.onScreenWindowIDs(pid:) names the windows enumerate() always lists, and WindowRecencyTracker.switchableWindowID(for:pid:onScreenWindowIDs:) remaps a focused tab surface onto the app's front on-screen window, applied on both the synchronous refresh path and the AX focus-changed callback. Hidden/minimized apps with no on-screen window keep current behaviour. 4 new tests, 58/58 pass. Rebuilt with the same Developer ID cert so TCC grants survived, installed to /Applications and relaunched: permissions intact, list verified correct (row 0 = current window, row 1 = previous, Chrome reappeared).
- **Interfaces:** NEW WindowEnumerator.onScreenWindowIDs(pid: pid_t) -> [CGWindowID] (front-to-back on-screen layer-0 windows passing the enumerator size guard). NEW static WindowRecencyTracker.switchableWindowID(for:pid:onScreenWindowIDs:) -> CGWindowID. CHANGED WindowRecencyTracker.recordFocusedWindow and refreshFrontmostWindow gained a defaulted onScreenWindowIDs parameter before the trailing lookup closure (existing call sites and trailing-closure tests unchanged). CHANGED the AX focusChangedCallback routes through the same resolution. Installed app now dev.mwitch.app 1.1.0 build 54.
